# Canonicalisation quality check and gate calibration

*Internal design/record document, lightly edited for the code release; dates are those of the original record.*

Evidence for the choice of the final canonicalisation (spec §9, 2026-10-30). The gate decisions
in `docs/fingerprint_gate.md` are not changed here.

Generated by `tools/canon/quality.py` (commit 579362b); the raw numbers and figure files are
not included in this release. Clips: the 300 gate clips of
each ASL dataset (asl_citizen, wlasl, how2sign, youtube_asl, openasl) plus 300 random train /
no-split clips >= 2 s of phoenix14t, autsl and isign (seed 0). Every clip is canonicalised from
the raw shards with canon-v1, -v2c, -v3, -v3.1 and -v4 (the same `canon_clip` as
`build_canon`) and also drawn as the raw image skeleton (isotropic pixels).

## §9 acceptance of canon-v4 (final): PASS

canon-v4 = the canon-v3 pipeline (hips never read and masked, per-frame shoulder-midpoint
centring, clip unit, face in its own scale, Savitzky-Golay 7/2 after the 25 fps resample) with
the canon-v1 orientation plus roll: yaw about y (median shoulder vector into the x-y plane),
then roll about z (onto +x); no pitch change.

All criteria hold in every dataset. The figures (`skeleton_<ds>.png`, columns "v4 front /
side"; `anim_<ds>.gif` = raw vs canon-v4) are upright and natural by eye: shoulders level, arms
hanging down in front and side views, head above the shoulders with the face in front, hands on
the wrists, signer's left on +x, no explosions. All 102 unit tests pass.

Notes: v4's up axis is 10-13° from the torso, a little more than canon-v1's 5-9°, because the
roll that levels the shoulders also tilts the torso line: in MediaPipe world coordinates the
shoulder line is ~12° from perpendicular to the shoulder -> hip line (canon-v1 keeps 12-13° of
shoulder tilt). About 1 % of OpenASL clips have any far-out frame at all (Tukey outliers of a median of 0).

## Earlier candidates (for the record)

- canon-v3.1 (§8, ear up axis) failed its acceptance: up axis 47-56° from the torso, because
  MediaPipe world places the ears (like the nose) 0.13-0.16 m in front of the shoulders; the
  shoulder -> ear vector is 48-58° from the shoulder -> hip direction in world coordinates but
  2-4° in the image plane (ear visibility 1.0; per-frame spread 2-4°, stable).
- canon-v2c / v3 (nose up axis) are pitched back 58-67°.
- canon-v1 (yaw only) keeps 12-13° of shoulder tilt.

## What the numbers show (all versions)

- Hands sit on the body wrists, the face at the head, left / right are correct, shoulder width
  is 1.000 everywhere (IQR < 0.0015), no exploded clips (a few YouTube-ASL / OpenASL / iSign
  clips in canon-v1 only, removed by per-frame centring).
- Limb proportions: forearm / upper-arm 0.71-0.82, hand size 0.23-0.32 shoulder widths;
  ASL Citizen hands are the largest relative to the shoulders (0.31, also in raw pixels), a
  recording property no version normalises.
- canon-v3 / v3.1 / v4: inter-ocular distance exactly 0.350 shoulder widths (IQR <= 0.004);
  body + hand jitter about 55 % lower than v1 / v2c.

## Interpreting the gate threshold

- Random halves of one dataset are not separable (0.46-0.55, chance 0.5).
- Three groups of disjoint signers *within one dataset* are separated at 0.75-0.80 P1
  (ASL Citizen, AUTSL) and 0.64-0.69 (WLASL), P2 up to 0.89, depending on version.
- The probes are reproducible to about ±0.001 (one clip in 900) between runs with sorted clips
  (BLAS); an earlier unsorted run (different CV folds) differed by up to ±0.03.

## Content preservation of the canon-v5 candidates (§10)

*The canon-v5 analysis code is not part of this release.*

Frozen-input linear ISLR (no learning on the pose): features = the P1 statistics of the whole resampled clip + a temporal-pyramid mean pose (whole clip, halves, quarters; 7 x 77 x 3), StandardScaler + logistic regression (C = 1); each of 3 seeds fits on a stratified 90 % subsample of the full train split, test = the full test split. AUTSL: official train (28,142) / test (3,742), 226 classes. LSA64 has no official split: signers 1-8 train (2,560) / signers 9-10 test (640), 64 classes. Acceptable = >= v4 - 2 points on both.

## Same sign, same motion? (§11)

*The cross-dataset analysis code is not part of this release.* RESONA-77 features were computed from the old RESONA-77 files.

**Gloss mapping** (ASL Citizen splits CSV `Gloss`, WLASL_v0.3.json `gloss`): lower-case, trailing variant number removed, non-alphanumerics removed. English words with more than one ASL Citizen variant (e.g. CANDY 1 / CANDY 2; 309 words) are excluded because the variants are different signs. A word is shared if it has clips in the official train and test splits of both datasets (clips with pose in canon-v4). **1180 shared glosses**; clips: ASL Citizen train 17,264 / test 14,380, WLASL train 9,087 / test 1,841. RESONA-77: all of these clips were matched by name in the old files (0 missing).

Features as in §10 (P1 statistics of the whole clip + temporal-pyramid mean pose), StandardScaler + logistic regression (C = 1, 300 iterations); 3 seeds, each training on <= 30 train clips per gloss (stratified draw; most glosses have fewer), tested on the full test splits. Within = the training dataset's own test split (ceiling); cross = the other dataset's test split; gap = within - cross.

### Reading (no version is adopted on this basis; §11)

- Canonicalisation makes the same sign more alike *across datasets*: cross-dataset DTW top-1 roughly doubles from raw image coordinates to canon-v1 / v4 / v5a (ASL Citizen → WLASL 0.057 → 0.099-0.107, WLASL → ASL Citizen 0.061 → 0.110-0.119, chance 0.005), and the ISLR transfer gap ASL Citizen → WLASL shrinks from 0.213 (raw) to 0.129-0.144, mostly because cross accuracy rises (0.078 → 0.089-0.108) while raw's higher within-ASL-Citizen ceiling (0.291, which includes the dataset's own camera framing) drops to about 0.235.
- Across datasets the same sign is still much less alike than within one: cross retrieval and cross ISLR are about half of the within-dataset ceilings for every version.
- Among the canonical versions the differences are small (one or two points, comparable to the seed / subset noise); v5a gives the highest ASL Citizen → WLASL transfer (ISLR 0.108, DTW top-5 0.276), v5c the highest WLASL → ASL Citizen ISLR (0.084) but the lowest within-ASL-Citizen retrieval.
- Across signers within a dataset, canon-v4 retrieves the same sign from other signers better than raw in ASL Citizen (top-1 0.408 → 0.428), WLASL (0.228 → 0.316) and AUTSL (0.216 → 0.372); LSA64 (10 signers, controlled recordings) is near ceiling for all versions. The same / different-gloss distance ratios overlap within their CIs for v1 / v4 / v5a; v5c's per-dataset standardisation makes them worse (AUTSL 0.550 → 0.643).
- RESONA-77 on ASL Citizen is near chance for ISLR (0.010 within): the old ASL Citizen file contains corrupted coordinates (x, y up to 3.8 × 10^5 px, noted in the gate inputs), which the shoulder normalisation does not repair; its DTW numbers are less affected. This is a data problem of the old file, not a property of the normalisation.
