# Dataset-fingerprint gate (canon-v1, canon-v2a, canon-v2b)

*Internal design/record document, lightly edited for the code release; dates are those of the original record.*

Spec: `docs/design/2026-10-29-canonicalisation-fingerprint-gate-design.md` §3 (gate) and §6 (canon-v2). Generated by `tools/canon/fingerprint.py`; the raw result JSON is not included in this release.

Task: which ASL dataset does a 2-s window come from? 300 train clips per dataset (rng seed 0), one random 2-s window each, resampled to 25 fps (50 frames); the same clips and windows for every version. 5-fold stratified, StandardScaler + L2 logistic regression C=1. P1 = per-group summary statistics (18 foresign groups: mean/std/range per coordinate, mean |vel|, mean |acc|, missing rate); P2 = window-mean pose (77 joints).

## Revised gate (§8, signer-calibrated)

Pass iff 3-way P1 <= S + 0.10, S = the highest within-dataset 3-signer-group P1 (ASL Citizen, AUTSL, WLASL; 300 clips per group, seed 0; `docs/canon_quality.md`) for the same version. Pre-registered for canon-v3.1; the other rows are post hoc.

## Run details

- canon-v1: 2026-10-29, canon files from commit 9b95a92 (all datasets).
- canon-v2a / v2b: 2026-10-30, commit 535751b; canon-v2c: commit 4a1a6e8; canon-v3: commit
  9369ebc. v2a/b/c and v3 were computed for the five gate datasets only
  (none passed, so nothing else was canonicalised with them). YouTube-ASL is one file per batch
  (`youtube_asl_b000NN.h5`, 43 files) in every version.
- The v2c amendment to spec §6 (commit 0dea67a) arrived before any v2 gate number had been
  computed or seen; all v2 probes were run once, together, after the v2c features existed.
  canon-v3 (§7, commit 711447b) was pre-registered after the v2 results and run once.
- canon-v3 pipeline (`canon.canon_clip(version="canon-v3")`): as v2c up to the clip frame
  (rotation R from shoulders + nose, per-frame shoulder-midpoint centring, division by the
  clip unit = median shoulder width); then the face joints (mouth8 + face18) are replaced by
  `x_nose + 0.35 * R (p - p_mesh_nose) / IOD`, where p are the face-mesh landmarks in
  isotropic pixels (x W, y H, z W) and IOD is the per-clip median distance between mesh 33 and
  263 in the same pixel space (frames with pose and face found); then the mask (hips 0),
  zeroing of invalid joints, the 25 fps resample, and finally Savitzky-Golay (window 7,
  order 2; edge points of a run use the polynomial fit of the first / last 7 frames, as
  scipy's mode="interp") per joint and coordinate over runs of valid frames >= 7 frames.
- Frame conventions: every version keeps the signer's left shoulder on +x and y pointing down
  (z = x × y). For v2c / v3 the spec's (x, up, x × up) frame is the same frame rotated 180°
  about x, which the probes cannot see. In v2b / v2c / v3 the hip slots are zero with mask 0,
  so the `trunk` group holds only the nose.
- Feature tables (`feats_*.npz`) and the clip / window selection file (unchanged since
  canon-v1) are not included in this release.
- Selection: train split; YouTube-ASL and OpenASL have no split in the manifests, so all their
  clips are eligible. Eligible clips (>= 2 s, pose found): asl_citizen 30,196, wlasl 9,197,
  how2sign 26,647, youtube_asl 8,399, openasl 1,892; 300 drawn from each.
- Windows: the same time span of the same clip for raw and all canon versions. Every version is
  resampled to 25 fps before the features (linear, nearest for the mask). Raw = MediaPipe
  normalised image (x, y) on the same 77 joints (`canon.raw77_2d`).
- RESONA-77 baseline (old RESONA-77 files `skeleton_resona77_<ds>.h5`, numpy port of the RESONA-77
  `shoulder_normalize`, valid = conf > 0.3): same clip and window for asl_citizen 300/300,
  wlasl 300/300, how2sign 299/300 (fps taken from the new data). The old YouTube-ASL / OpenASL
  files hold sentence segments, not full videos, so their 300 clips are an independent draw
  from the old train groups (rng seed 1). The old WLASL file is OpenPose without face.

## Observations (no further variant is proposed here)

- No canonicalisation passes: 3-way P1 is 0.923 (v1), 0.920 (v2a), 0.927 (v2b), 0.931 (v2c),
  0.929 (v3) against the required <= 0.700. Per §7 geometric canonicalisation stops here; how
  to proceed was decided separately (spec §8, §9).
- canon-v3 does what it was designed to do (see `docs/canon_quality.md`): the inter-ocular
  distance is fixed at 0.350 shoulder widths in every dataset (IQR <= 0.004), and body + hand
  jitter drops by about 55 % (e.g. asl_citizen 0.063 -> 0.028, youtube_asl 0.073 -> 0.034).
  The probe accuracy does not move: the separability does not come from these two properties.
- Within task type: isolated (asl_citizen vs wlasl, chance 0.5) stays at 0.92-0.94 P1 for all
  canon versions (RESONA-77 1.000); continuous (how2sign / youtube_asl / openasl, chance 1/3)
  is 0.66-0.70 for canon versions vs 0.973 for RESONA-77. How2Sign is separated in the
  continuous task while YouTube-ASL and OpenASL are mostly confused with each other.
- Calibration (`docs/canon_quality.md`): 3 groups of disjoint signers *within one dataset*
  are told apart at 0.74-0.78 P1 (ASL Citizen, AUTSL) and 0.64-0.67 (WLASL); random halves of
  one dataset give 0.48-0.52. So signer identity alone already exceeds the 0.70 threshold in
  two of three datasets with these features.
- Top separating features, canon-v3 3-way P1: sideways head offset relative to the shoulders
  (`contour.mean_x`, `trunk.mean_x` = nose x: how2sign -0.105 vs -0.082), face-shape spread
  (`contour.std_y`, `contour.std_x`, `eyes.std_x`), right-arm position / range
  (`r_arm.std_y`, `r_arm.mean_x`, `r_arm.range_z`). v2a/b/c: `contour.std_x`, `trunk.mean_x`,
  `contour.mean_x`, arm jitter (`l_arm.acc`, `trunk.acc`), arm vertical range (v2a).

Per-dataset fps_src of the 300 gate clips (rounded to 0.1):

Reading: (a) source-fps / resampling — velocity and acceleration alone give 0.78 (they do carry a dataset cue), but removing them leaves P1 unchanged (0.919), and asl_citizen vs wlasl at the same nominal fps (25 / 30) is as separable as with all clips; fps is not what the probe needs. (b) Missingness — the missing rates alone give 0.72, but without them P1 is 0.921. Neither channel explains the separability; it is carried by the pose statistics themselves (head offset, face shape, arm position / range).


Observation (no further variant proposed): per-dataset standardisation (v5c) removes the mean-pose cue (3-way P2 0.933 -> 0.516) but not the window statistics (P1 0.918 -> 0.929); retargeting (v5a) and the static head offset (v5b) change P1 by < 0.01. The separability is in how the pose moves and varies within a 2-s window, not in static proportions or the mean pose.
